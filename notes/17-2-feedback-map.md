## 발표자료에 넣을 핵심

개인용 AI를 팀 서비스로 옮기는 문제를 ‘모델 서버의 공동 사용’에서 끝내지 않고, **개인 대화 / 승인된 팀 기억 / 사용자별 하네스**의 세 층으로 나눴다. 같은 가중치를 공유해도 각 사람에게 보이는 정보와 허용할 행동은 다르게 설계해야 한다는 점을 사례와 도식으로 설명했다. 어느 내용을 공용 기억으로 승격하고 누가 승인할지는 확정된 해법이 아닌 팀의 설계 문제로 남겼다.

| 받은 피드백 | 본문 위치 | 반영 방식 |
| --- | --- | --- |
| AI는 주로 개인에 맞춰 사용되며, 팀이 한 박스/AI를 함께 쓰는 경우는 드물다. 팀 단위 활용은 열린 문제다. | 「팀 단위 AI의 공유 기억과 접근 권한」 111–115행, 135행 | 추론 서버 공유와 대화·기억 공유를 구분했다. 개발자 A가 찾은 규칙을 B가 재사용하는 사례를 두고, 대화 전체를 복사하지 않고 검토된 설계 결정과 출처만 공유하는 선택을 설명했다. 팀 기억으로 승격할 사실과 승인자는 열린 설계 문제로 명시했다. |
| 팀별 shared memory를 둔다면 사람별 정보 접근 권한을 어떻게 정할 것인가? | 117–119행, 운영 중 사고 사례 156–158행, 그림 `@fig-17-2-2` | 팀 기억 항목에 작성자·원자료·적용 팀·열람 대상·확인 시점을 남기고, 조회할 때 현재 권한을 다시 적용하도록 했다. 팀 이동 뒤 오래된 권한 캐시가 남아 다른 팀 코드가 노출되는 사고·복구 사례로 운영상의 결과를 보여 줬다. |
| 모델 capability를 어디까지 허용할 것인가? | 「모델 능력과 하네스의 행동 권한」 121–133행 | 모델의 답변 능력과 하네스의 행동 권한을 분리했다. 읽기·설명 → 격리된 공간의 수정 초안·검사 → 기본 브랜치 변경·배포의 순서로 권한과 사람의 승인 수준을 달리 설명했다. |
| 팀은 모델과 하네스를 어떤 식으로 함께 쓸 것인가? | 123–135행, 그림 `@fig-17-2-2`, 결론 164행 | 구성원별 대화와 권한을 가진 하네스가 공용 추론 서버를 사용하고, 승인된 팀 기억에는 별도의 조회·쓰기 권한을 거쳐 접근하는 구성을 제시했다. 이 구성을 실제 도식으로 만들었다. |
